# Rebuilding the experimental native engine

Use a Windows x86 MSVC toolchain with Windows SDK libraries, CMake and Git. These tools are only for building from source, not for users installing the release.

1. Clone https://github.com/mrxenginner/reVC and check out a26fff4af555a8a425ac9f17d1dd718d00d1f942 on miami. Initialize vendor/librw at 0ad67ee226ea51beb3f465cb8857195e4db16029.
2. Run `git apply /path/to/native-engine.patch` and then `git apply /path/to/multiplayer-bike-passenger-exit.patch` inside the clone.
3. Copy ViceTogether.cpp, ViceTogether.h, ViceTogetherNetwork.cpp, ViceTogetherWorld.cpp and ViceTogetherWorld.h from this folder into src/core. Copy vice-together.ico into src/skel/win.
4. Configure with CMake using Visual Studio 2022, Win32, LIBRW_PLATFORM=D3D9, REVC_AUDIO=MSS, MilesSDK_DIR pointing to vendor/milessdk, CMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded, REVC_WITH_OPUS=OFF, LIBRW_TOOLS=OFF, LIBRW_INSTALL=OFF and REVC_INSTALL=OFF.
5. Build Release. Copy the resulting reVC.exe into engine/native/reVC.exe in the launcher source. Retain ENGINE-LICENSE.md. Build the launcher with npm run dist.

The patch enables D3D9 correctly, conditions mpg123 on the OpenAL backend, selects the static C runtime, isolates native saves, starts a multiplayer free-roam world, keeps background instances updating, and calls the original bridge code before and after world simulation. No copyrighted assets or Miles runtime are provided here. The imported game supplies its own runtime.

VT_PORT is the launcher-owned loopback UDP port. VT_USER_DIR isolates saves. VT_AUTOSTART skips the frontend for private sessions. A 148-byte little-endian packet carries magic 0x31545656, type, slot and 34 floats. Player state includes four animation associations and gun aim. Type 1 is local state, 2 updates a remote ped and 3 removes it. Types 4/11 provide observations in VT_TEST_WALK or VT_OBSERVE. Real network traffic uses signed private WebRTC lobbies; this UDP transport is loopback only.

Native remote-player interpolation retains 16 recent snapshots per slot. At the normal 14 ms send cadence that provides about 210 ms of history, enough to cover the adaptive interpolation target up to 160 ms. This avoids requesting a jitter buffer longer than the available pose history. The launcher test harness can inject deterministic per-direction jitter with `VT_TEST_NETWORK_JITTER_MS`; those runs remain controlled same-PC simulations, not measurements of an ISP route.

VT_TEST_WALK injects actual pad movement for verification; VT_SPAWN_OFFSET separates players. VT_INPUT_DISABLED keeps the manual guest from taking controls. Types 5/7 set names/clothing, 6 reports FPS/window bounds, 9 reports supported native contacts and 10 applies shared health. Historical contact validation is bounded to 350 ms and is not complete lag compensation. Private sessions release mouse confinement by default.

Alpha 4 exchanges every inventory weapon selection (0–36) and actual weapon-atomic visibility with types 12/13, including NUTTERTOOLS loadouts. Types 14–16 relay and observe instant-hit shot effects, delayed to match avatar interpolation. Shotgun pellets and first-person rifle impacts are included; sniper bullet updates, projectiles and flame streams remain unfinished. Host-validated guest gun hits and melee now damage NPCs and return NPC health/reaction state. NPC fields 30/31 carry bleeding counters and body-part injury flags into the stock renderer. World transactions use 19/20 boundaries, 21 NPCs, 22 vehicles and 35 wheel/door/damage visuals. Vehicle frames also carry angular velocity in fields 23–25 so each copy can reproduce turning and rollover motion instead of applying different local spin. Types 28–32 coordinate host-driver/guest-passenger seating; press G near a shared car to request a guest seat. Type 43/44 applies the authorized guest driver's position, orientation, linear and angular velocity on the host. The host blends each received driver transform across its arrival interval at game-tick frequency instead of snapping only at packet rate. This is still a multiplayer prototype, not a claim of 1:1 vehicle or world physics.

Types 55/56 carry guest vehicle-spawn requests through the host launcher to the host native engine. The host validates the admitted peer, fresh living on-foot state, model allow-list and per-peer cooldown before spawning once near that peer. Guest vehicle-menu requests use the same path. Vehicle model classes include cars, bikes, boats, helicopters and planes in the interest-filtered world stream; helicopter/aircraft flight controls, rotor/propeller animation and passenger audio still require native gameplay verification.

World frame type 19 carries a host-authoritative `Come Fly With Me` state in field 23. In multiplayer, either player's stock cheat code toggles the host state; guests request the toggle and receive the same activation/deactivation help message. Other cheats, including weapon packs, stay local. The guest keeps vehicle and police replicas for up to two seconds after a complete snapshot omits them to prevent brief pop-out; this does not keep an actor alive after the host game streams it out.

Type 36 carries damage from the host native engine to its local launcher only. The host preserves local stock damage results and forwards NPC/police/vehicle damage to remote players; peers cannot submit this event through WebRTC. Remote proxy damage uses approximate player scaling and does not yet implement all immunity/armour rules. Wreck transitions replay stock vehicle explosions once. Guest attacks on NPCs, NPC shot effects, guest-aware police AI, projectiles and complete world interactions remain unfinished. Matching world snapshots does not establish 1:1 gameplay.

The upstream proof-of-usage contribution is public in [reVC PR #51](https://github.com/mrxenginner/reVC/pull/51). Its provenance hash is recorded in `THIRD-PARTY-NOTICES.md`; preserve that credit with builds of the native engine.

Alpha 16 lets both host and guests open the Ctrl+I Cheats menu and use the game's weapon-pack cheats. Shared-world time, weather and vehicle controls remain host-only to avoid guest-local changes that would immediately disagree with the authoritative world.

Alpha 35 sends host-driven vehicle snapshots to guests at gameplay cadence, matching the existing guest-to-host driver stream. Native guest replicas apply and interpolate those updates between rendered frames so the host's car no longer depends on the slower ambient-world snapshots. Same-PC native verification measured 14 ms median / 21 ms p95 packet arrival in one 25-second host-drive session; this is not a public-internet or passenger-seat test.

Alpha 36 raises the native driver-state capture target from 60 to 90 Hz. The lobby accepts up to 100 driver snapshots per second to absorb millisecond timer rounding while preserving a bounded rate. Two hidden Windows native clients measured 87.5 Hz received, 13 ms median / 15 ms p95 arrival, 129 Hz guest interpolation, and 143.6 FPS per game in a same-PC host-drive test. Passengers and public internet routes were not tested; higher cadence reduces state stepping but cannot eliminate route latency or divergent local physics.

Glass uses persistent model/position records (type 37), guest requests (40), and host grants (41). Late or re-streamed guests apply the retained pane's cracked/broken state through the stock glass implementation. Type 42 carries sequenced recent non-vehicle explosions; vehicle wrecks retain their existing stock explosion path. Host-attributed explosion damage now reaches shared player health. The two-engine native effects fixture verifies invisible, non-colliding glass in both object pools and guest health loss from a host-attributed nearby grenade. This does not verify all glass assets, identical particle randomness, every projectile, or internet play.
