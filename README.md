# ViceTogether — experimental friend-test build

[Download the Windows installer](https://github.com/notzeoxalt2/ViceTogether/releases/latest) · [Private invitation page](https://notzeoxalt2.github.io/ViceTogether/)

Install Setup once. Open your profile in the sidebar and save your player name. Import your original PC Vice City folder once, or let the separate personal offline edition prepare its supplied assets. Host a private lobby and send its invitation. Your friend installs the same version, opens the invitation, finishes game setup inside the lobby if needed, and waits for the host to start. Keep the launchers open while playing.

The installed edition checks GitHub releases and downloads launcher updates automatically. Updates apply on exit without uninstalling, preserving settings, social history, saves and cached game files. The portable edition needs manual replacement. For the personal offline edition, the original bundled assets are preserved outside the app install folder as a durable repair source before import. Later launcher-only updates do not need to include those assets again. The preservation test replaces a temporary install folder and verifies both cached play readiness and repair; a silent installed alpha.3-to-alpha.7 NSIS upgrade also preserved settings, cache and saves.

Friends pair through a private invite without accounts. Both launchers must be open for chat and live presence; there is no offline delivery. Each device caches up to fifty messages per friend locally, with twelve friends supported in this preview. Anyone with a pairing invite can attempt to pair; share with one trusted friend. "Not connected" does not prove a friend is offline.

Overhead labels now exclude the local player. Remote ped markers use the stock radar and main map. These changes compiled; no additional gameplay was opened for visual verification at the user's request.

This is an experimental prototype. It has not passed fresh Windows or cross-network testing, and gameplay synchronization remains incomplete. A free public TURN candidate failed a forced-relay data test, so it is not enabled. Cloudflare metered TURN was explicitly declined. Direct WebRTC, public signaling and STUN are enabled; restrictive NAT/firewall combinations may prevent joining. No guaranteed connectivity or guaranteed zero-latency synchronization is claimed. Fifteen game modes are deferred.

Developer releases: push source fixes normally; bump package.json and package-lock.json together, then push the matching vVERSION tag. The Windows workflow runs unit tests, builds Setup/portable/update metadata and uploads a GitHub release. Existing installed clients discover the new release. Source pushes alone do not create an app update. Do not publish personal offline installers or original game files on GitHub.

The default packaged multiplayer launcher remains Electron. The Rust/Tauri preview is source-only and has no native multiplayer bridge yet.

## Earlier prototype notes

This is an experimental Windows prototype, not a finished GTA multiplayer release.

The launcher now opens a searchable game Library. Vice City is the first supported integration; additional games will need their own working multiplayer mods. Engine creation, asset setup and installation detection now go through the bundled game registry. See PLATFORM.md for the multi-game direction and GitHub release plan. No second game is available yet. The GitHub release feed is configured for launcher updates.

Install the setup executable or open the portable edition. Select your legally obtained original PC Vice City folder once. The standard installer caches your existing game assets locally. The separately named personal offline installer includes the user-supplied assets and prepares them automatically on first run. The imported original gta-vc.exe is not used or modified. You do not need Node, Python, Docker or a separate game server to run the packaged application.

Host: open Host, create a private lobby, copy the short room code or invite link, and send it to your friend. Friend: install the same launcher, import their own game files, and paste the invitation into Join. After the lobby shows both players, the host starts the experimental on-foot session. Each launcher opens the native engine directly. Keep the launchers open while playing.

Installed builds register vicetogether:// invitation links. Opening a supported custom link launches the installed application; many chat clients will not make custom schemes clickable, so paste into Join if needed. The HTTPS invite page is published through GitHub Pages; the room secret stays in the URL fragment. Install the app, then return to the page to open the invitation. Portable builds do not register the protocol automatically. Invite codes contain private lobby credentials: share only with intended players.

Your PC hosts the private session. WebRTC uses free third-party signaling and STUN; the game does not need a rented dedicated server. There is no TURN service configured. Restricted NATs, blocked signaling or corporate networks can prevent connections. Testing two games on one PC does not verify connections between different networks.

Verified: the engine loads this user's game assets, two native games run simultaneously, both move under automated pad input, real WebRTC transports their state, and both engines create remote player peds. Screenshots show both players together. See ../verification/desktop-tests.json for the measured results and limitations. The recorded position metric compares with recent source positions and permits lag; it does not establish visual smoothness or low internet latency.

Current prototype: shared player transforms and animation, inventory weapon visibility and several instant-hit shot effects, limited host-owned ambient entities, clock/weather intensity, vehicle wheel/door/damage visuals, persistent glass breaks, sequenced non-vehicle explosions, and initial empty-car host/guest driving. The host now prioritizes hit NPCs in the next snapshot; hidden same-PC checks verified guest melee and gun damage reaching both game instances. Captures select up to 48 pedestrians and 32 vehicles within 350 metres of host-known players. Guests keep their own ambient population outside a 110-metre overlap with the host, so NPCs in distant guest areas are not yet the same entities seen by everyone. Guests press F for a driver seat; either player presses G for a passenger seat. Host-native NPC/police/environment damage feeds shared health. The two-engine glass/grenade fixture verifies broken panes becoming invisible and non-colliding in both engines and guest health falling to 17.5. The 35-second road fixture kept driver and guest in the same car over 320 metres at approximately 144 FPS with matching seated bone shapes. The host-side passenger uses the current authoritative seat; the guest rides a buffered car replica, so the test evaluates the host-side passenger against the authoritative driver trajectory including seat separation. These are local engine observations, not proof of pixel-identical effects or smooth internet driving.

Initial guest driving is locally verified; approved guest instant-hit gunfire is recast on the host for NPC/vehicle damage. Ctrl+I now opens a Cheats menu for either player; guests can use the original weapon-pack cheats, while shared-world time, weather and vehicle controls stay host-authoritative. Not finished: a full-featured cheat system, comprehensive vehicle entry/exit and NPC combat, NPC shot effects, guest-aware police pursuit, fully shared NPC populations in distant areas, complete weapons/projectiles/combat, complete world interactions, full prediction and lag compensation, 15 game modes, an end-to-end installed-update walkthrough, Discord Rich Presence, fresh Windows testing and internet/NAT testing. Singleplayer uses the original mission script; private sessions use a separate free-roam startup. Movement still validates client transforms rather than using fully authoritative host physics. This is not 1:1 multiplayer.

Settings and saves are stored under the application's Windows user-data directory; assets are cached locally. If the system drive is too full, first import automatically places the cache beside the existing installation on its other drive, in ViceTogether-library. Check & repair restores corrupted cached assets from the import source. This release points its update feed at the GitHub release downloads. The native game now supports 30, 60, 120, 144, 240 and uncapped frame-rate preferences and fullscreen. Actual frame rate depends on the computer. Two simultaneous games measured approximately 144 FPS in the recorded local test. Higher-rate compatibility with every mission and physics interaction has not been established.

Alpha 2 adds named players, automatic Tommy clothing colour variations, source walk/run and basic fight animation timing, a bounded interpolation buffer, and an experimental host-owned melee-health system. A real stationary pad-input melee fixture registered hits and shared damage in two actual engines. This does not establish moving-target accuracy, complete combat, gunfire synchronization or zero-latency movement. The 90-second stationary melee test recorded 14 contacts, two deaths and two respawns; see ../verification/melee-long. This does not establish accuracy against freely moving players. Private worlds continue simulating when menus are open.

The standard installer contains no original game assets. The personal offline packaging script builds locally from user-supplied assets for which the user has stated permission. It never uploads or publishes the result. The offline edition automatically prepares its bundled assets once on first run; subsequent launches reuse the cache. Its repair source is the installed offline-game folder, so preserve that folder. This prototype is not a final multiplayer release.

Short codes use ten random unambiguous characters (for example K7M4P-9Q2RX); links are 31 characters, such as vicetogether://join/K7M4P-9Q2RX. No short-code database is required. The code is a bearer secret: anyone holding it can attempt to join. Short-code joins pin the first valid signed host roster for that session; older full invitations carry an explicit host fingerprint. Keep codes private.

Alpha 3 fixes remote RenderWare model transforms, suppresses automatic multiplayer pause menus on focus loss, adds bounded historical melee-contact validation, and adds adjustable mouse sensitivity. Native tests open on the secondary monitor in separate corners and fall back to the primary when none is connected. Private-session mouse confinement is disabled by default; the manual host-only test disables guest input and mutes its sound. Physical mouse feel still needs user evaluation.

Alpha 4 fixes networking timers being throttled when the native game covers the launcher, preserves a normalized full-body base pose underneath partial attack animations, retires stale partial poses, and scopes the original player-skin render override so shirt recoloring survives the actual draw. The first two players use red and green shirts. The 40-second two-game walking check in ../verification/skeleton-color-network-fix passed with approximately 143–144 FPS, zero model-root discrepancy, checked head-to-foot bone distances, and a closest-recent-position discrepancy of approximately 0.04–0.14 metres at the 95th percentile. This metric permits interpolation delay and is not a guarantee of internet latency or visual quality. Pistol equipment and native contact validation are experimental; full gun combat remains under test. The latest ambient-world changes replace independent guest population with bounded host replicas; NPC shooting, guest-aware police and full interactions remain unfinished.

## Source and development

The packaged runtime requires no development tools. To develop: install Node, run npm ci, npm run bundle, then npm start. Unit checks: npm test. Desktop checks: npm run test:desktop -- --disable-gpu. Actual two-game check: set VT_TEST_GAME_ROOT to your own game folder and run Electron with --self-test --native-test --disable-gpu. VT_TEST_SHOW=1 shows both game windows during this automated check. Keep game assets out of source archives and the standard installer. The personal offline script is a separate local packaging path for the assets the user stated permission to include.

The native source patch and original bridge files are in engine/native-source. Clone the pinned reVC source with its librw submodule, apply the patch, and build x86 D3D9/MSS with static MSVC runtime. See BUILD.md there. The upstream source's proof-of-usage contribution is recorded in [reVC PR #51](https://github.com/mrxenginner/reVC/pull/51); preserve the provenance hash in THIRD-PARTY-NOTICES.md with redistributed native builds.

Windows can display its normal network-access permission prompt. That prompt was observed during the installed-app walkthrough; it was not accepted automatically. Cold and warm custom invitation links were verified to reach the installed launcher.

No fresh Windows VM or Windows Sandbox runtime was available on this machine, so the required clean-install test has not been performed. This project must not be described as finished.
